# 행운부동산공인중개사사무소 gongjangtown 스타일 리디자인 설계

작성일: 2026-07-05
상태: 승인 대기 (사용자 리뷰 게이트)

## 1. 개요 & 목표

기존 코인베이스풍 디자인 언어와 홈 구성을 폐기하고, 참조 사이트
[gongjangtown.com](https://www.gongjangtown.com/)(동아부동산 "공장타운")의
**정보밀집형 공장·창고 전문 포털** 구성·기능·스타일을 행운부동산공인중개사사무소 사이트에 재현한다.

- 행운의 매물·회사정보·브랜딩은 그대로 행운 것을 사용한다.
- 기술 스택은 현행 Next.js 16 / Supabase / Netlify를 유지한다 (참조 사이트의 frameset/PHP 구조는 채택하지 않는다).
- 실행 방식은 **제자리 재스킨**: 데이터층·SEO·지도·shadcn 프리미티브 등 동작하는 배관을 재사용하고, 디자인 토큰과 페이지 구성만 교체한다.

성공 기준:
- 홈이 곧 검색 페이지가 되어, 방문자가 필터로 공장·창고·토지 매물을 바로 훑을 수 있다.
- 정보밀집형(조밀한 카드, 표 같은 정렬, 필터 전면) 시각 언어로 전환된다.
- 고령 접근성(18px 루트, 큰 탭 타깃, 고대비), SEO, 전화우선 CTA 등 기존 하드 제약은 유지된다.
- 전체 테스트 / tsc / eslint / 프로덕션 빌드가 통과한다.

## 2. 참조 사이트 분석 (gongjangtown)

- 구성: 홈(main.php)이 곧 검색 페이지. 좌측 매물 카드 그리드 + 우측 다중 필터 사이드바.
- 필터: 종류(공장·창고/토지), 평수 구간, 거래유형(매매/전세/월세), 매매가 구간, 월세 구간, 보증금 구간, 면적 구간.
- 매물 카드: 종류, 위치(구·동), 평수(건물/임대), 가격(매매 만원 또는 보증금/월).
- 부가: ㎡↔평 변환기, 무료 문자상담 폼, 방문자 통계, 관심등록(favorites), 테마별 브라우징.
- 페이지: 홈 / info_list.php(필터 목록) / info_view.php(상세) / company.php(회사소개) / admin.
- 스타일: 히어로 없음, 흰/회색 배경 + 웜(오렌지) 액센트, 표 같은 조밀 레이아웃, 실용주의 B2B.

## 3. 비목표 (명시적 제외)

다음은 이번 리디자인에서 **채택하지 않는다**:

- **무료 문자상담 폼 / 리드 수집** — 오너(60대·전화우선·저관리)가 폼 제출을 모니터링해야 하고 개인정보 보관·알림 인프라가 필요해 유지보수 제약과 충돌. 연락은 기존 전화/문자 CTA로 대체.
- **방문자 통계** — 허영 지표, 추적 인프라 불필요.
- **관심등록(favorites)** — 로그인/계정 필요, 고령 사용자에 부담.
- **테마별 큐레이션** — 소규모 사무소 매물 수엔 과함. 향후 확장 여지로 남김.
- **참조 사이트의 고유 그래픽·문구·이미지 복제** — 같은 인천 서구 직접 경쟁사이므로 시각 자산을 그대로 베끼지 않는다. 구성·기능·밀도 등 일반적 업종 패턴만 차용.
- **frameset / PHP / GIF 버튼 등 구식 기술** — 모던 스택 유지.
- 관리자 CMS 신규 구축 — 매물 입력은 기존 Supabase 흐름을 그대로 사용.

## 4. 설계 원칙 & 스타일 방향

- **정보밀집형·실용주의**: 히어로 이미지와 넓은 여백을 제거하고 검색·매물을 전면에 둔다.
- **표 같은 정렬 + 조밀한 카드**: 라운드는 줄이고(현행 `rounded-3xl` → `rounded-md`급), 하이라인 보더·구분선을 적극 사용, 패딩을 조인다.
- **밀도와 접근성의 균형**: 밀도는 레이아웃·간격에서 확보하고, 본문/탭 타깃 크기는 접근성 기준(18px 루트, 탭 타깃 ≥ 44px, 고대비) 아래로 내리지 않는다. 메타 텍스트만 상대적으로 작게.
- **브랜드 연속성**: 행운 블루(`#0052ff`) 액센트 유지 + 중립 그레이 크롬. (웜톤 전환은 토큰 교체만으로 가능하도록 설계.)
- **전화우선**: 큰 전화 CTA 상시 노출 원칙 유지.

## 5. 디자인 토큰 변경 (globals.css)

- 기존 색 토큰(brand/ink/muted/canvas/hairline/surface-dark 등)은 유지한다. 색상 팔레트 자체는 바꾸지 않는다.
- 라운드/간격 스케일을 조밀하게 재조정한다. 카드·패널 기본 라운드를 축소하고, 구분선/보더 사용을 늘린다.
- shadcn 프리미티브(Button/Card/Badge/Dialog)의 기본 클래스를 조밀 스타일로 재스킨한다 (라운드·패딩 축소). API/변형(variant)은 유지해 호출부 변경 최소화.

## 6. 정보 구조(IA) & 라우트

| 라우트 | 역할 |
|---|---|
| `/` | 홈 = 검색 페이지. 사무소 한 줄 소개 + ㎡↔평 변환기 + 필터 사이드바 + 매물 그리드 |
| `/listings` | 동일한 검색 UI (네비 "매물검색", 그리고 네비 매매/임대 딥링크 대상) |
| `/listings/[slug]` | 매물 상세 (정적 생성 유지) |
| `/about` | 회사소개 (회사정보 중심 + 지도) |
| `/404` | 유지 |

- `/`와 `/listings`는 공통 컴포넌트 `ListingSearch`를 렌더한다. `/`는 소개 한 줄 + 변환기를 상단에 두고, `/listings`는 "매물검색" 헤더로 시작한다. 코드 중복 없이 동일 검색 엔진을 공유.
- 두 라우트 모두 `dynamic = 'force-static'`. 빌드 시 `getPublishedListings()`로 전체 공개 매물을 로드해 클라이언트 컴포넌트에 전달하고, 필터링은 클라이언트에서 수행한다 (소규모 인벤토리 전제).
- 네비게이션: `홈` / `매물검색` / `매매`(→`/listings?deal=매매`) / `임대`(→`/listings?deal=임대`) / `회사소개`.
- SEO는 정적 생성되는 개별 상세 페이지 + sitemap이 담당한다. 필터 쿼리 URL은 공유/북마크 편의를 위한 것이며 별도 정적 페이지를 만들지 않는다.

## 7. 컴포넌트 / 페이지 명세

### 7.1 공통

**Header** — 현행 2단 구성(문의 바 + 메인 내비) 유지하되, 조밀 스타일 재스킨. 네비에 매매/임대 딥링크 추가. 전화 CTA 유지.

**Footer** — gongjangtown처럼 회사정보 밀집형으로 정리: 상호·대표·사업자번호·사업자등록번호(있으면)·주소·대표전화·팩스(있으면)·영업시간·네이버 지도 링크. 조밀한 표 느낌.

### 7.2 홈(=검색) & 매물목록: `ListingSearch`

클라이언트 컴포넌트. 입력: `listings: Listing[]`(전체 공개 매물), `showIntro?: boolean`.

구성:
- **UnitConverter** (상단): ㎡↔평 양방향 변환. 순수 계산, 클라이언트 전용, 백엔드 없음.
- **FilterSidebar** (데스크탑 우측 스티키 / 모바일 상단 접이식):
  - 종류(propertyType): 전체/공장/창고/토지/기타
  - 거래유형(dealType): 전체/매매/임대
  - 평수 구간(대지면적 기준): 전체 / 60평 이하 / 60~100 / 100~200 / 200~300 / 300평 이상
  - 가격 구간(거래유형 종속): 거래유형=매매 → 매매가 구간, =임대 → 월세 구간, =전체 → 가격 구간 숨김
  - 결과 건수 표시, 초기화 버튼
- **ListingGrid**: 조밀한 `ListingCard` 그리드. 빈 상태 메시지(전화 안내).
- 필터 상태는 URL 쿼리(`type`/`deal`/`area`/`price`)와 동기화(`useSearchParams` + `router.replace`, shallow). 최초 진입 시 쿼리로 초기 필터 세팅(네비 매매/임대 딥링크 지원).

**ListingCard (조밀 재디자인)** — 종류·거래유형 배지, 위치(구·동), 평수(대지/건물, 평), 가격(`formatDealPrice`, 읽기 쉬운 표기 유지). 현행보다 패딩·라운드 축소, 정보 밀도 상향.

### 7.3 매물상세 `/listings/[slug]`

현행 구조 유지하되 조밀 재스킨: 제목 → 이미지 슬라이더 → **조밀 스펙표**(SpecTable, 표 느낌 강화) → 설명 → **NaverMap(지도는 여기서 사용)** → 공유 버튼(링크복사/문자) → 전화 CTA 밴드.

### 7.4 회사소개 `/about`

회사정보 중심 페이지 유지, 조밀 재스킨. 사무소 정보 표 + NaverMap.

## 8. 필터 로직 & 데이터

`applyFilters`를 순수 함수로 확장(TDD 대상):

```ts
export type AreaBucket = '전체' | '~60' | '60-100' | '100-200' | '200-300' | '300~';
export type PriceBucket =
  | '전체'
  // 매매(price, 원)
  | '매매:~5천' | '매매:5천-1억' | '매매:1-2억' | '매매:2-5억' | '매매:5-10억' | '매매:10-20억' | '매매:20억~'
  // 임대(monthlyRent, 원)
  | '임대:~100만' | '임대:100-300만' | '임대:300-500만' | '임대:500-1000만' | '임대:1000만~';

export interface ListingFilter {
  propertyType?: PropertyType | '전체';
  dealType?: DealType | '전체';
  areaBucket?: AreaBucket;   // 대지면적(landAreaM2) → 평 기준
  priceBucket?: PriceBucket; // 매매가(price) 또는 월세(monthlyRent), 거래유형 종속
}
```

- 평수 구간: `pyeong(landAreaM2)`로 평 환산 후 구간 판정. `landAreaM2`가 null이면 평수 구간 필터 시 제외.
- 가격 구간(매매): `price`(원) 임계값 판정. 임계값 예: 5천만=50,000,000, 1억=100,000,000 …
- 가격 구간(임대): `monthlyRent`(원) 임계값 판정. `monthlyRent`가 null이면 임대 가격 구간 필터 시 제외.
- 각 구간은 `{ value, label, test(listing) }` 형태의 데이터로 정의해 드롭다운과 필터 로직이 같은 소스를 공유한다.
- 구간 임계값·라벨은 상수 테이블로 관리(향후 조정 용이).

## 9. 재사용 vs 폐기

**재사용(내부 배관)**: Supabase 데이터층(`lib/listings`, `lib/types`, `lib/format`), SEO(`lib/seo`, `JsonLd`, 메타데이터), `NaverMap`, shadcn 프리미티브(재스킨), 라우팅/정적생성 구조, 테스트 인프라.

**폐기/교체**: 코인베이스풍 여백 디자인 언어, 히어로 헤드라인 홈, 홈의 지도+CallPanel 전면 배치, 현행 단순 `FilterPanel`(→ 확장된 `FilterSidebar`로 대체), 현행 `ListingBrowser`(→ `ListingSearch`로 대체). `CallPanel`은 홈에서 제거(전화 CTA는 헤더/밴드로 충분).

## 10. 접근성 제약 (유지)

- 루트 18px, 탭 타깃 ≥ 44px, 고대비 유지.
- 가격은 읽기 쉬운 표기(`매매 6억 6,000만원`) 유지. 참조 사이트의 압축 만원 표기(`66,000`)는 채택하지 않음.
- 필터 버튼/드롭다운은 명확한 라벨·`aria-pressed`/`aria-label`, 키보드 접근 보장.
- 모바일 필터 접이식은 `aria-expanded`/`aria-controls`로 상태 노출.

## 11. 테스트 전략

- **TDD 신규**: 확장 `applyFilters`(평수·가격 구간, 거래유형 종속 가격, null 필드 처리), `UnitConverter` 변환 계산.
- **갱신**: 현행 `ListingBrowser`/`FilterPanel` 테스트를 `ListingSearch`/`FilterSidebar` 테스트로 이전(필터 콜백, aria 상태, 결과 건수, URL 동기화).
- **유지**: 상세/카드/지도/SEO/Header/Footer 테스트는 유지하되 구조 변경분 반영.
- 게이트: `vitest run` / `tsc --noEmit` / `eslint` / `npm run build` 전부 통과.

## 12. 범위 밖 (Out of scope)

문자상담 폼·리드 수집, 방문자 통계, 관심등록, 테마별 큐레이션, 챗봇, 관리자 CMS 신규, 참조 사이트 시각 자산 복제, 스택 교체.
